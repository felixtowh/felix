关闭后，前端聊天页面将隐藏「我的习惯」入口，Dify 应用也无法调用习惯接口。
🔐

调用密钥

Dify Workflow 中的 HTTP 请求节点调用 Portal 习惯接口时，需要在 Header 中携带此 Key。
Portal 端需要完成的操作

步骤 1：打开上方「接口开关」，并确保「调用密钥」已填写。开关状态改变后会自动保存。

步骤 2：进入「应用管理 → 编辑应用」，勾选「启用习惯功能」。只有勾选的应用，其聊天页面才会显示「📝 我的习惯」入口。

Dify 端需要完成的操作

在 Dify Workflow 中配置 HTTP 请求节点，调用 Portal 的习惯接口：

{% raw %}// ========== 推荐：直接获取习惯纯文本（GET）========== // Dify 的 HTTP 请求节点输出的 body 是字符串， // 加 ?format=text 可直接拿到纯文本，无需写代码转换器 方法: GET URL: {{#portal_base_url#}}/api/external/memories?format=text Headers: X-Portal-Key: {{#portal_key#}} X-Portal-User-Id: {{#portal_user_id#}} // 下游节点（如 LLM）直接引用习惯内容： 用户的个人习惯：{{#http_node.body#}} // ========== 高级：获取 JSON 格式（需要代码转换器）========== 方法: GET URL: {{#portal_base_url#}}/api/external/memories Headers: X-Portal-Key: {{#portal_key#}} X-Portal-User-Id: {{#portal_user_id#}} // 写入用户习惯（POST） 方法: POST URL: {{#portal_base_url#}}/api/external/memory Headers: Content-Type: application/json X-Portal-Key: {{#portal_key#}} X-Portal-User-Id: {{#portal_user_id#}} Body (JSON): { "action": "add", "content": "用户新习惯内容" } // action 可选值: add / update / delete{% endraw %}
💡 配置提示
推荐用法：URL 后面加上 ?format=text，Dify 的 HTTP 请求节点返回的 body 就是习惯纯文本（如 "爱吃萝卜;爱吃清淡"），在下游 LLM 节点中直接引用 {% raw %}{{#http_node.body#}}{% endraw %} 即可，不需要写代码转换器。

空习惯处理：如果用户没有任何习惯记录，返回的是空字符串 ""，Dify 不会报错，Prompt 中该位置自然为空，无需额外判断。

变量说明：
• {% raw %}{{#portal_user_id#}}{% endraw %} = Portal 用户账号（userid，唯一标识，用于 API 调用）
• {% raw %}{{#portal_key#}}{% endraw %} = 调用密钥
• {% raw %}{{#portal_base_url#}}{% endraw %} = Portal 服务器地址

思考功能配置

Portal 端需要完成的操作

进入「应用管理 → 编辑应用」，勾选「启用思考功能（sikao）」。只有勾选的应用，其聊天页面才会显示下拉切换按钮。

Dify 端需要完成的操作

在 Dify 应用的「编排 → 对话开场白 → 变量」中添加一个选择器（select / 下拉选项）类型的变量：

  • 变量名：sikao
  • 标签：回答方式（或包含「方式」二字）
  • 选项 1：快速回复 —— 对应不思考模式（默认轻量回复）
  • 选项 2：深度思考 —— 对应思考模式（启用推理增强）
  • 默认值：快速回复

配置完成后，Portal 会在聊天页面顶部渲染一个下拉选择器。用户选择「深度思考」时，Dify 会收到 sikao=深度思考，你可以在 Workflow 的条件分支节点中根据该值走不同的模型分支。

💡 常见误区
只勾选 Portal 里的开关，但 Dify 里没有配置 sikao 变量 → 下拉按钮不会显示。
只在 Dify 里配置了变量，但 Portal 里没有开启开关 → 下拉按钮也不会显示。两个条件必须同时满足。

智能瞬时回复

Portal 端功能开关

当 Dify 工作流执行时间较长时（如含外部 API 调用、知识检索、复杂计算），前端会自动显示 AI 正在处理的状态提示，缓解用户等待焦虑。

无 LLM 回复策略：即使不配 LLM 参数，功能也会生效。未配置 LLM 时，系统按以下固定策略自动返回状态提示：
触发时间回复内容
第 1 次轮询（5秒）正在为您处理中，请稍候...
第 2 次轮询（10秒）还在努力处理中，请耐心等待...
第 3 次轮询（15秒）处理时间较长，感谢您的耐心等候...
第 4 次轮询（20秒+）仍在处理中，马上就好...
第 6 次轮询（30秒+）非常抱歉让您久等了，仍在处理中...

配置 LLM 后，将使用 AI 动态生成状态提示，效果更自然。

开启智能瞬时回复
关闭后，前端聊天页面不会显示 AI 处理状态提示。
使用 LLM 生成自然回复
开启后，使用下方配置的 LLM 动态生成状态提示；关闭则使用固定模板回复。
